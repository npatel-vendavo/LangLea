# Roadmap / Backlog

Living document for features to be implemented. Update checkboxes as work lands; add new ideas under the relevant category with a priority.

Priority legend:

- **P0** — important, planned next
- **P1** — valuable, scheduled
- **P2** — nice to have / exploratory

## Content & learning experience

- [ ] **P0** Three-level depth control for generation — let the user pick how many main topics / subtopics / items the agent should produce (currently fixed: 6-10 topics, 4-7 subtopics, 2-4 items).
- [ ] **P0** Regenerate a single section — ask the AI to re-expand one topic or re-roll one item without regenerating the whole module.
- [ ] **P0** Edit items manually — allow adding, removing, and reordering topics/subtopics/items in the tree before or after generation.
- [ ] **P1** Mark items complete — a per-item "done" toggle so the module doubles as a progress tracker.
- [ ] **P1** Add a final "quiz / checkpoint" section per subtopic generated by the AI (questions + answers) to test understanding.
- [ ] **P1** Prerequisites and dependencies — let the agent tag prerequisite topics so the tree shows "learn before" relationships.
- [ ] **P2** Recommended learning path — a linear study plan derived from the tree (week-by-week / session-by-session schedule).
- [ ] **P2** Import/export the tree in standard formats (OPML, Anki-flavored CSV, `.mdx` for documentation sites).

## Study notes

- [ ] **P1** Note quality options — ask for deeper/longer notes, code examples, diagrams, or an explanation at different levels (beginner/intermediate/advanced).
- [ ] **P1** Streaming study-note generation (SSE) so long notes appear progressively.
- [ ] **P2** Link-related items — when a note mentions another concept in the module, turn it into a clickable reference.
- [ ] **P2** Image/diagram support in notes (the agent requests/generates diagrams, or embeds them in markdown).

## Chat & AI capabilities

- [ ] **P0** Chat history server-side persistence — mirror chat sessions to disk alongside modules so history survives browser cache clears and is portable across devices.
- [ ] **P1** Chat context controls — pick which item/section/note the chat should use as context, or attach the whole module.
- [ ] **P1** Follow-up suggestions — after each assistant answer, offer suggested follow-up questions.
- [ ] **P1** Copy/regenerate individual chat messages.
- [ ] **P2** Long-term chat memory — summarize past sessions so later chats can reference earlier questions and answers.
- [ ] **P2** Multiple chat threads per subject (named sessions) instead of one growing log per subject.

## Persistence & collaboration

- [ ] **P1** Delete or archive saved modules from the dashboard.
- [ ] **P1** Rename a module/subject.
- [ ] **P1** Sorted/filtered dashboard — sort by date, items, or name; search across saved modules.
- [ ] **P2** Share a module — export a self-contained bundle (markdown + JSON) that another user can import.
- [ ] **P2** Multi-user support — store modules per user account instead of per browser.

## Reliability & performance

- [ ] **P1** Pause/cancel a running job explicitly (currently cancel only stops the client view; the job keeps running server-side).
- [ ] **P1** Concurrency and cooldown settings — expose retry count, round count, and parallelism so users can tune for stricter endpoints.
- [ ] **P2** Graceful degradation when the endpoint lacks `response_format`/JSON support (fallback parsing is already implemented).
- [ ] **P2** Token/budget estimator — estimate requests before generating "all notes" to avoid surprise costs.

## UX & platform

- [ ] **P1** Mobile-friendly workspace — better responsive behavior for the three-panel layout on small screens (drawers/overlays).
- [ ] **P1** Keyboard shortcuts — collapse/expand tree, focus chat, jump between panels.
- [ ] **P2** Dark/light theme toggle.
- [ ] **P2** Onboarding tour for first-time users.
- [ ] **P2** PWA support (offline access to saved modules via localStorage + service worker).

## Notes on process

- Before implementing a P0 item, open a branch named `YYMMDD-feat-<topic>` and keep commits small.
- Update this file (check the box) in the same change that implements the feature.
